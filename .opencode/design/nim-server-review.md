# Nim server adversarial review

## Blockers

**B1. The owner has no lifetime independent of its first client.** The first process becomes vault owner (`.opencode/design/nim-server.md:35`). The default command is MCP (`bin/sketchdex.js:89`), and the current stdio server exits when stdin closes (`mcp/server.js:314`). Closing the first MCP client would therefore kill the app, SSE streams, and other MCP sessions. Define a detached or reference-counted owner, adoption, and crash recovery. Test an app plus two MCP clients, close the first client, then kill the owner. Clients must fail or reconnect cleanly, and stale IPC endpoints must be removed safely.

**B2. `npx` contradicts the no-Node guarantee.** The plan keeps `npx -y sketchdex` (`nim-server.md:37`) but requires default command trees to contain no Node (`nim-server.md:181`). Current help recommends that command (`bin/sketchdex.js:66`). npm and npx are Node programs. Narrow the guarantee to no Node descendant started by Sketchdex after installation, or ship a native installer and make the direct binary the supported MCP command. Measure from the native server, not from npm.

**B3. Vault identity and locking are underspecified.** `createStore` only calls `path.resolve` (`server/store.js:15`) and serializes writers inside one process (`server/store.js:31`). Symlinks, Windows case variants, junctions, and UNC aliases can name one vault but acquire different locks. A lock inside the vault disappears when the vault is deleted. Network shares may not honor `flock` or `LockFileEx`. Canonicalize path and volume identity, put the lock outside the deletable vault, and fail closed on unsupported filesystems. Never break a live OS lock using PID or boot metadata. Authenticate the relay and serialize HTTP enabling with owner startup. Test aliases, two vaults, owner crash, SMB, and NFS without elevation.

**B4. The route table is not a parity contract.** The plan says all API responses are JSON and lists exact methods (`nim-server.md:66`). Actual behavior differs. Unknown `/api/*` paths and non-GET `/api/vault` fall through to the SPA (`server/middleware.js:160`, `server/middleware.js:203`). Every method on `/api/events` opens SSE (`server/middleware.js:186`). Every non-POST method on `/api/agent` returns ops (`server/middleware.js:191`). `OPTIONS /api/scenes` is 405 without `Allow`, while static handling accepts all methods (`server/serve.js:43`). Unknown or extra scene subpaths are ignored, so `GET /api/scenes/id/foo` returns the scene and `POST /api/scenes/id/duplicate/foo` duplicates it. Empty bodies bypass the content-type check (`server/middleware.js:48`), API segments are not decoded (`server/middleware.js:159`), malformed static escapes return plain-text 400, and static responses have no cache validators (`server/serve.js:57`). Ordinary errors are `{error}`, conflicts add `code` and `rev`, and outer failures can be empty 500 (`server/middleware.js:64`, `server/middleware.js:290`, `server/serve.js:86`). SSE sends `no-cache, no-transform` and `keep-alive`; JSON uses bare `application/json`. `/mcp` malformed JSON is a middleware `{error}` 400, while the SDK adds 406, 405 with `Allow`, and 202; `/mcp/` falls to the SPA. Generate a baseline matrix for status, headers, body, HEAD, OPTIONS, trailing slashes, encoded paths, and fallback before implementation. Mark intentional hardening changes.

**B5. The npm launcher cannot work as written.** One root package cannot select a POSIX shell launcher and a Windows batch launcher through one `bin` target. npm generates Windows shims from that target and its shebang. The current package has one Node bin (`package.json:30`). Platform packages exposing `sketchdex` also collide with the root bin. Use one non-JavaScript polyglot launcher or a tiny native launcher, and give platform packages no public bin. The smallest proof is a packed root plus Windows x64 package tested with global install, `npx`, `--omit=optional`, and a monorepo. In a monorepo, bare `npx sketchdex` can select a stale local version. Pin `@latest` or document direct-binary use.

## High

**H1. Chronos is plausible, but unearned.** Chronos gains SSE, chunked responses, streaming bodies, middleware, process I/O, and Windows IOCP (`nim-server.md:44`). It loses standard-library simplicity and adds macro-heavy debugging. Chronos 4.4 requires bearssl, httputils, results, stew, and unittest2 at build time; only linked code ships. `std/asynchttpserver` now has Windows support, keep-alive, configurable body caps, read deadlines, and chunked request decoding. For this loopback-only server it loses little. Prototype both and prefer the standard library unless Chronos reduces total code or fixes a measured limitation. JSON parsing, serialization, SVG conversion, inspection, geometry, and gzip must not run on the event loop (`server/svg.js:37`, `server/inspect.js:55`). Test a 32 MiB save while SSE heartbeats continue.

**H2. Native MCP compatibility is unproven.** The plan lists seven methods (`nim-server.md:96`) but omits version negotiation, batches, notifications, cancellation, protocol headers, and exact errors. HTTP is stateless with JSON response mode (`server/middleware.js:19`). Checkout stdio hot-reloads the worker and sends `tools/list_changed` (`mcp/server.js:139`), which the plan drops. Dispatch has custom errors, a 120 KiB text ceiling, a 150 KiB image ceiling, and spilling (`mcp/tools.js:36`, `mcp/tools.js:606`). Dispatch checks required keys but not types (`mcp/tools.js:622`); strict native validation would change behavior. `sketchdex_info` exposes Node-only fields (`mcp/tools.js:524`). Minimum proof is the official SDK client over stdio and HTTP, every supported protocol version, malformed and batched JSON-RPC, notifications, exact 19 schemas, instructions, seven resources, results, errors, and pipe-close behavior. The riskiest incompatibility is stateless HTTP lifecycle and error-shape parity.

**H3. Store parity has observable edge cases.** Planned flush, directory sync, and Windows write-through are stronger than the current rename (`server/store.js:47`). Startup temp cleanup is also new. Preserve or explicitly change that `ifRev` allows creation when the file is missing (`server/store.js:235`), `touch:false` skips index updates (`server/store.js:248`), and revisions use JavaScript number formatting (`server/store.js:67`). A valid but stale index is not rebuilt, and `patchIndex` does not add a missing scene (`server/store.js:106`, `server/store.js:134`). Agent mutation snapshots once, retries while `attempt < 3`, preserves `files`, and claims the exact revision (`server/agent.js:168`). Test delete-and-recreate, stale indexes, fractional mtimes, same-size writes, and retry exhaustion.

**H4. History and watcher parity need exact contracts.** Snapshots exclude `files`, cap at 20, use 16-character hex ids, and expose compressed byte counts (`server/history.js:29`, `server/history.js:116`). A different deflate changes visible `bytes` even when decompressed JSON matches. Claims never expire (`server/history.js:78`). The watcher starts on first subscribe, debounces 120 ms, uses a 2.5 second fallback, does not deduplicate by revision, and stops after a watch error until resubscription (`server/watch.js:25`, `server/watch.js:51`, `server/watch.js:100`). The previous-state cache holds five scenes (`server/agent.js:58`). Scene deletion clears history before moving the file to trash (`server/middleware.js:305`). Always-on polling changes event counts and when external history appears. Bounded queues and slow-client drops are new. Specify these behaviors and compare SSE order.

**H5. Render is incomplete as described.** The temporary listener serves every `dist/` asset, not only three routes (`mcp/render.js:284`). Without assets the render page cannot load Excalidraw or fonts. It posts `text/plain` JSON (`src/render.ts:30`), and discovery includes Vivaldi and Chrome Canary (`mcp/render.js:83`). Current Windows and macOS discovery skips `PATH`, and a forced Electron path works only in a checkout. Cleanup kills only the browser parent (`mcp/render.js:352`). Serve embedded assets safely, separate the callback body limit from the API limit, authenticate the listener, use a process job or group, and await listener and profile cleanup. Tiling and crops can remain in `src/render.ts`; preserve their payload and result shapes.

**H6. Phase gates arrive too late.** Phase 2 bundles ownership, storage, history, watcher, SSE, HTTP, assets, and app entry (`nim-server.md:178`), unlike the earlier split (`.opencode/design/nim-core.md:242`). The core build points at a missing entry file (`scripts/build-core.mjs:28`). Move four spikes earlier: cross-platform lock and IPC recovery, HTTP stack comparison, native MCP conformance, and no-Node npm launch. Split Phase 2 into storage, ownership, HTTP, and app units. Every runtime gate must launch the native binary directly and inspect its OS process tree.

## Medium

**M1. A fixed 32 MiB limit can reject valid scenes.** The app sends the whole scene, including `files`, in one PUT (`src/lib/store.ts:147`), while the current server has no cap (`server/middleware.js:44`). Make the limit configurable, test image-heavy scenes near the boundary, and document 413 as an intentional change.

**M2. Security checks need a parity decision.** The loopback regex accepts invalid IPv4 text and any numeric port (`server/middleware.js:70`). Origin validation checks only host, not scheme or port, and allows a missing Origin (`server/middleware.js:85`). Static files bypass the Host guard (`server/serve.js:81`). Preserve or harden these rules explicitly.

**M3. Size and release assumptions need measurement.** Here `dist/` is 8.1 MiB, the npm tarball is 2.74 MB, and unpacked size is 8.41 MB. A stripped Nim server with raw embedded assets, docs, metrics, schemas, gzip, and Chronos will likely occupy 10 to 15 MiB. Chronos may add 0.5 to 2 MiB of linked code. Electron is roughly 150 to 250 MiB installed. Compress web assets and avoid shipping the MCP SDK or Electron. Remove the Node `prepare` requirement from registry installs (`package.json:63`), handle omitted optional packages, provide musl and glibc Linux variants or state the limit, and verify macOS notarization and Windows Authenticode rather than merely attaching signatures.

## Low

**L1. CLI parity is unspecified.** Preserve or intentionally change flags, exit codes, port scanning, browser opening, docs topics, and version output (`bin/sketchdex.js:29`, `bin/sketchdex.js:105`). Add golden CLI tests.

## Verdict

The design is not safe to build as written. The native architecture is viable, but ownership lifetime, strict no-Node packaging, canonical vault locking, and route parity can each force a late redesign. The single riskiest unknown is cross-process vault ownership on Windows, macOS aliases, and network filesystems, because a silent second writer can lose user data.
